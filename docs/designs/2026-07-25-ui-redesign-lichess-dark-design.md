# UI 重塑 — Lichess 深色专业风全屏聚焦可折叠布局

## Intent Contract

**intent**: 将 UI 从暖纸墨色三栏布局重塑为 Lichess 深色专业风全屏聚焦可折叠布局，统一视觉、布局、交互与信息层次。

**constraints**:
- 不破坏现有对弈闭环（三方主体组合、流式思考、走法合法性、持久化恢复）
- 不改变后端 API 与持久化结构（纯前端重塑）
- 保留所有现有功能（风的加护、悔棋、重开、引擎分析、评估柱、音效、成本统计）
- 棋子 SVG（Cburnett）保持不变

**success_criteria**:
- 启动后直接显示棋盘（无 Welcome 页），无对局时显示"开始对弈"浮层
- 深色主题统一应用，Lichess 经典棕色棋盘 + `#629924` 绿色强调
- 右侧合并面板默认显示（走法历史/分析/设置三标签），可一键收起为纯棋盘
- 顶部工具栏一键可达所有核心操作（开始/继续/重开/悔棋/引擎/面板收起）
- 走法历史在面板中实时更新（替换当前 Phase A 左侧留白占位）

**risk_level**: medium

## Verification Contract

**verify_steps**:
  - run tests: `npm run build`（构建通过）
  - run tests: `npm run check`（svelte-check 0 errors）
  - check: 启动应用，无对局时棋盘居中 + "开始对弈"浮层
  - check: 点"开始对弈"后进入对局，右侧面板默认显示走法历史标签
  - check: 切换标签页到引擎分析/设置，内容正确
  - check: 点顶部"面板收起"按钮，右侧面板隐藏，棋盘纯全屏
  - check: 走一步棋，走法历史实时更新，评估柱/分析面板同步刷新
  - check: 切换主体组合（人vs鳕鱼/鳕鱼vs鳕鱼等），布局不破坏
  - check: 恢复对局后显示"继续对局"按钮，点击后 AI 驱动
  - confirm: 深色主题统一，无残留暖纸墨色，棋盘为 Lichess 棕色

## Governance Contract

**approval_gates**:
  - 本设计文档审批（已完成）
  - writing-plans 生成 workflow 后执行前审批
  - 视觉重塑完成后人工确认质感（深色主题/配色/对比度）
  - 交互流程人工手感验证（标签页切换/面板收起/按钮响应）

**rollback**:
  - 重塑集中在前端组件（App.svelte/Board.svelte/Settings.svelte/AnalysisPanel.svelte + CSS 变量）
  - git revert 相关文件即可恢复暖纸墨色三栏布局
  - 不涉及后端/持久化迁移，无需数据回滚

**ownership**: 用户（产品决策）+ 开发者（前端实现）

## Decisions

| # | 决策 | 选择 | 拒绝的替代 |
|---|---|---|---|
| 1 | 视觉风格 | Lichess 深色专业风（背景 #161512 / 表面 #262421 / 文字 #e8e6e3） | 暖纸墨色深度优化 / Chess.com 休闲风 / 现代极简留白 |
| 2 | 布局结构 | 全屏聚焦可折叠（棋盘居中最大化，右侧面板默认显示可收起） | Lichess 经典三栏 / 四角浮动 / 底部命令栏 |
| 3 | 棋盘配色 | Lichess 经典棕色（浅格 #f0d9b5 / 深格 #b58863） | Lichess 现代灰蓝 / Chess.com 绿色 / 保留当前棋盘色 |
| 4 | 强调色 | Lichess 绿 `#629924`（主按钮/选中/高亮） | 暖金色（当前）/ 蓝色 / 红色 |
| 5 | 交互流程 | 顶部工具栏 + 右侧合并面板（浮动控制面板风） | 启动直入棋盘 / Welcome 简化 / 四角浮动 |
| 6 | 面板组织 | 默认显示右侧合并面板（走法历史/分析/设置三标签），可一键收起 | 默认隐藏按需开 / 走法历史常驻其他浮动 / 四角浮动 |
| 7 | Welcome 页 | 移除，启动直接显示棋盘（无对局时叠加"开始对弈"浮层） | 保留 Welcome 简化 / 保留 Welcome 不变 |

## Surface

**App.svelte** — 主布局改造：
- 移除 `.welcome` 欢迎页结构与 CSS，启动直接渲染 `.board-area`
- 无对局时棋盘显示空局面，叠加"开始对弈"浮层按钮（绝对定位居中）
- 新增顶部工具栏 `.toolbar`，包含核心操作按钮：开始/继续、重开、悔棋、引擎切换、面板收起
- 移除 `.drawer`（底部设置抽屉）相关结构与 CSS，`drawerOpen` 状态仅用于窄屏退化
- 右侧面板 `.side-panel` 常驻，含标签页切换（`activeTab: "history" | "analysis" | "settings"`）+ 收起按钮
- 面板收起状态 `panelCollapsed: boolean`，收起后 `.side-panel` 隐藏，棋盘纯全屏
- CSS 变量全部替换为深色主题色板
- 保留底部状态栏（状态文案 + 用量 + 成本统计）
- 保留"风的加护"开关，移到顶部工具栏或底部状态栏

**Board.svelte** — 棋盘视觉适配：
- 棋盘配色改为 Lichess 棕色（`--board-light: #f0d9b5` / `--board-dark: #b58863`）
- 高亮色改为 `--highlight: rgba(98,153,36,0.4)`
- 选中格、上一步、将军格、合法目标格的视觉语言适配深色主题与绿色强调
- 思考条、举棋标记、举棋箭头、评估箭头配色适配深色主题
- 评估柱紧贴棋盘左侧（已在 .board-area 内，保持 flex 布局）
- 棋子 SVG（Cburnett）保持不变，确认深色背景下对比度（白棋描边清晰）

**Settings.svelte** — 适配面板标签：
- 移除抽屉容器相关样式，作为右侧面板的"设置"标签页内容渲染
- 保留所有设置项：API Key / 模型 / 思考模式 / 伪思考 / 思考语言 / 思考强度 / 最少思考token / 自洽采样 / 白方主体 / 黑方主体 / 音效 / 鳕鱼难度 / 执方
- "开始对弈 / 应用设置 / 退出对局"按钮保留在设置标签内
- "继续对局"按钮逻辑保留（恢复对局 + 当前轮到方是自动主体时显示）

**AnalysisPanel.svelte** — 适配面板标签：
- 移除独立标题栏与关闭按钮（窄屏抽屉模式保留），作为右侧面板的"分析"标签页内容渲染
- 引擎未加载时显示居中"启用引擎"按钮，加载后显示深度/MultiPV 控制 + PV 列表
- PV 列表占满剩余高度，`overflow-y: auto`
- 配色适配深色主题

**新增 MoveHistory.svelte** — 走法历史组件：
- 新建组件，作为右侧面板的"走法历史"标签页默认内容
- 显示走法列表：两列布局（白方 / 黑方），左侧回合编号，右侧 SAN 走法
- 当前走法高亮（`--highlight` 背景）
- 可滚动（`overflow-y: auto`），自动滚动到当前走法
- 从 `$gameState.move_history` 读取（后端已提供，需确认是否含 SAN，若仅有 UCI 则前端用 chess.js 转换）

**EvalBar.svelte** — 配色适配深色主题：
- 评估柱背景改为深色主题表面色
- 白方/黑方优势色块保持白/黑，但边框适配深色
- 数值标签字号 ≥11px，颜色 `--ink`

**CSS 变量层** — 全局色板替换：
- `--bg` / `--surface` / `--surface-2` / `--ink` / `--ink-muted` / `--ink-faint` / `--line` / `--accent` / `--accent-soft` / `--danger` / `--highlight` / `--board-light` / `--board-dark` 全部替换为 Lichess 深色主题值
- 字体变量 `--font-display` / `--font-sans` 保持不变
- 间距/圆角变量 `--sp-*` / `--r-*` 保持不变

## Risks & Open Questions

| # | 风险/问题 | 缓解/方向 |
|---|---|---|
| 1 | 深色主题下棋子 SVG（Cburnett）对比度需验证 | Cburnett 是 Lichess 同款，深色背景下白棋描边清晰；若有问题加 drop-shadow 增强 |
| 2 | 顶部工具栏 + 底部状态栏 + 右侧面板可能挤压棋盘 | 棋盘 `flex-shrink: 0` + `min-size` 保护；面板可一键收起；窄屏 <900px 退化为抽屉 |
| 3 | 走法历史组件新建，move_history 是否含 SAN 需确认 | 若后端仅提供 UCI，前端用 chess.js 从初始 FEN 重放转换 SAN；或后端补全 SAN 字段 |
| 4 | 设置从抽屉改为标签页，原有 `drawerOpen` 状态逻辑需重构 | 用 `activeTab` 状态统一管理标签切换，`drawerOpen` 仅用于窄屏退化 |
| 5 | 移除 Welcome 页后首次使用引导缺失 | 空棋盘 + "开始对弈"浮层已足够引导；设置标签页有 API Key 输入提示 |
| 6 | 顶部工具栏按钮数量较多可能拥挤 | 仅放核心操作（开始/继续/重开/悔棋/引擎/面板收起），其他放设置标签；窄屏可滚动 |
| 7 | 面板收起后用户可能找不到展开入口 | 顶部工具栏"面板收起"按钮切换为"展开面板"文案，状态可逆 |
| 8 | 走法历史自动滚动可能干扰用户手动浏览 | 检测用户滚动事件，用户上滚时暂停自动滚动，回到底部时恢复（与 reasoning 容器同策略） |
